DAL PRIMO SCHEMA AL DIAGRAMMA FINITO

Guida all’uso di UML4ALL

Scrivi gli elementi e le loro connessioni nel pannello a sinistra: il diagramma prende forma nel pannello a destra. Tutta l’elaborazione avviene nel tuo browser.

1. Crea il primo diagramma

  1. Scegli un esempio dal menu Parti da un esempio: rete, flusso di approvazione, architettura logica o schema essenziale.
  2. Modifica o incolla il codice nel pannello Sorgente. Con Anteprima live attiva, il diagramma si aggiorna mentre scrivi.
  3. Per aggiornare il disegno manualmente, disattiva l’anteprima live e premi Genera oppure Ctrl+Invio (Cmd+Invio su Mac).
  4. Usa + e − per lo zoom e ⤢ per adattare il diagramma alla larghezza disponibile. L’anteprima cresce in altezza con il disegno: scorri la pagina per esplorarlo. Premi Solo diagramma per usare tutta la larghezza, poi Mostra codice per tornare all’editor.

Trascina il divisore tra codice e diagramma per cambiare la larghezza dei pannelli. Puoi selezionarlo con Tab e usare le frecce sinistra e destra. Con Blocchi pronti inserisci un elemento e il relativo codice con un clic: l’etichetta viene selezionata per modificarla. Gli identificatori sono unici. Se il codice contiene errori, correggili prima di inserire altri blocchi.

2. Salva ed esporta

  • Salva codice scarica un file .ret modificabile. Puoi usare anche Ctrl+S o Cmd+S quando il cursore è nell’editor.
  • Per riprendere un progetto salvato, apri il file .ret con un editor di testo e copia il contenuto nel pannello Sorgente.
  • Esporta SVG scarica il diagramma come immagine vettoriale, utilizzabile in documenti e presentazioni. Il pulsante si attiva quando il codice è valido e l’anteprima è aggiornata.
  • Il salvataggio automatico conserva l’ultimo codice in questo browser, quando consentito. Per conservare più progetti, scarica un file .ret per ciascuno. Scegliere un esempio o incollare altro testo sostituisce il codice corrente: salvalo prima, se vuoi conservarlo.

3. Scrivi uno schema di rete

Il diagramma ha un titolo, elementi con identificatori unici e collegamenti. app è l’identificatore usato nelle connessioni; "API" è il testo visibile nel disegno. I gruppi zone raccolgono gli elementi di una stessa area.

Usa una dichiarazione per riga. Apri un blocco con { alla fine della dichiarazione e chiudilo con } su una riga dedicata.

diagram "Il mio schema" {
  direction right
  zone "Applicazioni" {
    server app "API" {
      ip = "10.0.1.10"
      note = "Servizio principale"
    }
    database db "Archivio"
  }
  app -> db : SQL
}

4. Disegna un flusso di lavoro

Usa start e end per inizio e fine, task per le attività e decision per una scelta. Scrivi gli esiti sui collegamenti dopo i due punti.

diagram "Approvazione" {
  direction down
  start inizio "Inizio"
  task richiesta "Invia richiesta"
  decision verifica "Approvata?"
  task esegui "Esegui attività"
  end fine "Fine"

  inizio -> richiesta -> verifica
  verifica -> esegui : sì
  verifica -> fine : no
  esegui -> fine
}

5. Consulta la sintassi

Elementi disponibili: cloud, router, firewall, switch, network, server, database, service, actor, task, decision, start, end, node.

  • zone "Nome" { e group "Nome" { creano gruppi annidati. Collega gli elementi contenuti usando i loro identificatori.
  • a -> b -> c collega una sequenza. a <-> b è bidirezionale; a -- b non ha frecce; a --> b è tratteggiato.
  • a -> b : Etichetta aggiunge una descrizione al collegamento. Usa le virgolette per etichette con caratteri speciali.
  • direction right oppure direction down sceglie l’orientamento per tutto il diagramma.
  • Proprietà dentro un elemento: ip, subnet, vlan, protocol, owner, note, color. Scrivi nome = "valore" su una riga; per esempio vlan = "10" o color = "#dbeafe". Le proprietà di rete sono descrittive.
  • Identificatori: lettere ASCII, numeri, trattino e underscore; primo carattere una lettera o underscore. Etichette fra virgolette; \n per andare a capo.
  • Commenti su una riga con // oppure #. Puoi scrivere i collegamenti prima delle dichiarazioni, purché tutti gli elementi siano dichiarati nel diagramma.

6. Layout, spaziatura e schemi complessi

Il layout predefinito è layout layered: usa ELK nel Web Worker, senza servizi esterni. Riserva spazio alle etichette e dispone i collegamenti ad angolo retto. Puoi scegliere layout simple per il precedente motore a curve. spacing compact è la spaziatura predefinita; usa spacing normal o spacing wide per aumentare le distanze. Questi due comandi si scrivono solo nel diagramma principale.

direction right e direction down indicano l’orientamento. Possono essere scritti anche in group e zone. Nel layout ELK con collegamenti tra gruppi prevale l’orientamento globale per mantenere coerenti i percorsi gerarchici; con layout simple le direzioni locali sono indipendenti. Per leggere un singolo gruppo in ELK selezionalo dal menu Vista: il suo orientamento diventa quello della vista.

diagram "Esempio completo" {
  direction right
  layout layered
  spacing compact
  group "Applicazioni" {
    direction down
    server api "API" {
      ip = "10.0.1.10"
      subnet = "10.0.1.0/24"
      vlan = "20"
      protocol = "HTTPS"
      owner = "Team IT"
      note = "Prima riga\nSeconda riga"
      color = "#dbeafe"
    }
    database db "Archivio"
    api -> db : "Scrittura / lettura"
  }
}

Vista Automatica: oltre 25 elementi mostra una panoramica per gruppi. Panoramica per gruppi: riassume i gruppi, nasconde i collegamenti interni e accorpa quelli esterni equivalenti. Se le etichette accorpate sono troppo lunghe mostra il numero dei collegamenti. Dettaglio completo: mostra ogni elemento e ogni collegamento. Gruppo: mostra solo le sue attività e i collegamenti interni. Queste viste preservano tutto il codice: non cancellano elementi.

Esporta SVG scarica la vista visualizzata. Salva codice conserva sempre il diagramma completo. Nessun layout può rendere leggibili decine di etichette in pochi pixel: usa una vista per gruppo o aumenta lo zoom. Gli incroci necessari possono rimanere, soprattutto in presenza di cicli.

7. Comandi, scorciatoie e limiti

Il contenitore iniziale è diagram "Titolo" {. Chiudi ogni blocco con } su una riga dedicata. zone e group sono equivalenti; non hanno identificatori collegabili e non accettano proprietà. Le proprietà elencate sopra si applicano agli elementi: il colore riguarda il riempimento, non i bordi o il testo. Direzioni disponibili: solo right e down. Sintassi Mermaid, HTML, classi, file esterni e script non sono supportati.

-> è una freccia continua, <-> bidirezionale, -- una linea senza frecce e --> una freccia tratteggiata. Una catena può avere un’etichetta, applicata a ogni tratto. Per collegare più destinazioni scrivi una riga per destinazione. Sono ammessi cicli e auto-collegamenti. Un elemento senza etichetta usa l’identificatore come testo. Nelle stringhe usa \n, \" e \\ per a capo, virgolette e barra inversa.

Ctrl/Cmd+Invio: genera. Ctrl/Cmd+S nell’editor: scarica il codice. Tab nell’editor: inserisce due spazi. Esc: chiude la guida. Il divisore si usa con il mouse oppure, dopo averlo selezionato con Tab, con frecce sinistra/destra; Shift aumenta il passo, Home/End raggiungono i limiti. I pannelli sono impilati su mobile. Zoom: da 8% a 300%; il pulsante Adatta ripristina l’adattamento automatico alla larghezza.

Limiti: 100.000 caratteri, 5.000 righe, 4.096 caratteri per riga, 250 elementi, 500 collegamenti, 100 gruppi, 12 livelli di gruppi annidati. Identificatori fino a 64 caratteri, titoli ed etichette fino a 300, valori delle proprietà fino a 500. I colori devono essere esadecimali a sei cifre. Ogni proprietà può comparire una sola volta per elemento. Il Worker viene interrotto dopo 3 secondi e l’SVG non può superare 2 MB. In apertura diretta come file il motore di compatibilità usa il layout semplice: per ELK e le viste usa il sito web.

8. Correggi gli errori

  • Elemento non dichiarato: controlla che l’identificatore usato nel collegamento corrisponda a un elemento dichiarato.
  • Identificatore duplicato: assegna un identificatore diverso a ciascun elemento, anche se si trova in un altro gruppo.
  • Parentesi o virgolette mancanti: chiudi ogni blocco con } e ogni etichetta con le virgolette.
  • Il messaggio sotto l’editor indica la riga da controllare. Se esiste una versione valida precedente, l’anteprima continua a mostrarla finché il codice non viene corretto.

Layout ELK con percorsi ortogonali ed etichette con spazio dedicato. Nei grafi densi gli incroci fra collegamenti restano possibili: usa la panoramica e le viste per gruppo. Fino a 250 elementi, 500 collegamenti e 100 gruppi. Titoli ed etichette: massimo 300 caratteri; proprietà: 500 caratteri. Chiudi la guida con ✕ o con il tasto Esc.
