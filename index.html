DAL PRIMO SCHEMA AL DIAGRAMMA FINITO

Guida all’uso di UML4ALL

Scrivi gli elementi e le loro connessioni nel pannello a sinistra: il diagramma prende forma nel pannello a destra. Tutta l’elaborazione avviene nel tuo browser.

1. Crea il primo diagramma

  1. Scegli un esempio dal menu Parti da un esempio: rete, flusso di approvazione, architettura logica o schema essenziale.
  2. Modifica o incolla il codice nel pannello Sorgente. Con Anteprima live attiva, il diagramma si aggiorna mentre scrivi.
  3. Per aggiornare il disegno manualmente, disattiva l’anteprima live e premi Genera oppure Ctrl+Invio (Cmd+Invio su Mac).
  4. Usa + e − per lo zoom e ⤢ per adattare il diagramma alla larghezza disponibile. L’anteprima cresce in altezza con il disegno: scorri la pagina per esplorarlo. Premi Solo diagramma per usare tutta la larghezza, poi Mostra codice per tornare all’editor.

2. Salva ed esporta

  • Salva codice scarica un file .ret modificabile. Puoi usare anche Ctrl+S o Cmd+S quando il cursore è nell’editor.
  • Per riprendere un progetto salvato, apri il file .ret con un editor di testo e copia il contenuto nel pannello Sorgente.
  • Esporta SVG scarica il diagramma come immagine vettoriale, utilizzabile in documenti e presentazioni. Il pulsante si attiva quando il codice è valido e l’anteprima è aggiornata.
  • Il salvataggio automatico conserva l’ultimo codice in questo browser, quando consentito. Per conservare più progetti, scarica un file .ret per ciascuno. Scegliere un esempio o incollare altro testo sostituisce il codice corrente: salvalo prima, se vuoi conservarlo.

3. Scrivi uno schema di rete

Il diagramma ha un titolo, elementi con identificatori unici e collegamenti. app è l’identificatore usato nelle connessioni; "API" è il testo visibile nel disegno. I gruppi zone raccolgono gli elementi di una stessa area.

Usa una dichiarazione per riga. Apri un blocco con { alla fine della dichiarazione e chiudilo con } su una riga dedicata.

diagram "Il mio schema" {
  direction right
  zone "Applicazioni" {
    server app "API" {
      ip = "10.0.1.10"
      note = "Servizio principale"
    }
    database db "Archivio"
  }
  app -> db : SQL
}

4. Disegna un flusso di lavoro

Usa start e end per inizio e fine, task per le attività e decision per una scelta. Scrivi gli esiti sui collegamenti dopo i due punti.

diagram "Approvazione" {
  direction down
  start inizio "Inizio"
  task richiesta "Invia richiesta"
  decision verifica "Approvata?"
  task esegui "Esegui attività"
  end fine "Fine"

  inizio -> richiesta -> verifica
  verifica -> esegui : sì
  verifica -> fine : no
  esegui -> fine
}

5. Consulta la sintassi

Elementi disponibili: cloud, router, firewall, switch, network, server, database, service, actor, task, decision, start, end, node.

  • zone "Nome" { e group "Nome" { creano gruppi annidati. Collega gli elementi contenuti usando i loro identificatori.
  • a -> b -> c collega una sequenza. a <-> b è bidirezionale; a -- b non ha frecce; a --> b è tratteggiato.
  • a -> b : Etichetta aggiunge una descrizione al collegamento. Usa le virgolette per etichette con caratteri speciali.
  • direction right oppure direction down sceglie l’orientamento per tutto il diagramma.
  • Proprietà dentro un elemento: ip, subnet, vlan, protocol, owner, note, color. Scrivi nome = "valore" su una riga; per esempio vlan = "10" o color = "#dbeafe". Le proprietà di rete sono descrittive.
  • Identificatori: lettere ASCII, numeri, trattino e underscore; primo carattere una lettera o underscore. Etichette fra virgolette; \n per andare a capo.
  • Commenti su una riga con // oppure #. Puoi scrivere i collegamenti prima delle dichiarazioni, purché tutti gli elementi siano dichiarati nel diagramma.

6. Correggi gli errori

  • Elemento non dichiarato: controlla che l’identificatore usato nel collegamento corrisponda a un elemento dichiarato.
  • Identificatore duplicato: assegna un identificatore diverso a ciascun elemento, anche se si trova in un altro gruppo.
  • Parentesi o virgolette mancanti: chiudi ogni blocco con } e ogni etichetta con le virgolette.
  • Il messaggio sotto l’editor indica la riga da controllare. Se esiste una versione valida precedente, l’anteprima continua a mostrarla finché il codice non viene corretto.
